# Конструктор видео-квизов «Угадай песню» — контекст для Claude

Отвечай пользователю по-русски. Термины — по `GLOSSARY.md` (раунд, а не тур; слайд, а не экран;
отрывок, а не фрагмент; обложка альбома и обложка для соцсетей; оформление, а не тема). Пользователь делает YouTube-квизы «угадай песню», работает
на Ubuntu 24.04 и запускает всё сам. Проект начат в облачной сессии Claude. Там YouTube, Deezer
и iTunes были недоступны, поэтому скачивание и поиск обложек проверены только на подставных
данных. **Первое, что стоит сделать здесь, — прогнать сценарий на реальных ссылках YouTube**
(см. «Что проверить в первую очередь»).

## Что уже решено (и почему)

- **Структура ролика:** заставка квиза (заголовок + многострочное приветствие) → список раундов
  (без заголовка, `rounds_card`, убирается `timing.rounds = 0`; музыка и озвучка как у заставки) → для каждого раунда:
  заставка раунда (название + правила) → вопросы раунда → «Ответы · {round}» → ответы раунда → финал.
  Нумерация вопросов начинается заново в каждом раунде. Раунды хранятся в `project["rounds"]`
  (`id, title, rules`), у трека есть поле `round`. `normalize` переносит треки без раунда в первый раунд,
  а квизу без раундов создаёт раунд `r1`. Порядок задают раунды, внутри раунда — порядок `tracks`.
  У раунда может быть своё время на вопрос (`seconds`, иначе `timing.question`, см. `question_seconds`).
  Пауза `timing.gap` стоит в начале каждого вопроса: кольцо прорисовывается и держится полным
  с полным числом секунд, звука нет, потом одновременно стартуют отсчёт и музыка (`pre` в
  `SpectrumRing.draw`). При gap = 0 кольцо прорисовывается уже под музыку. После ответа своя пауза
  `timing.answer_gap`: слайд держится без звука.
  Если у трека задан `start2`, вопрос состоит из двух отрывков по половине времени с паузой
  `SPLIT_PAUSE` между ними (`track_sound` в `scenario.py`). Отсчёт идёт через всю цепочку, длительность слайда
  вопроса уже включает паузу. В интерфейсе `fragLen(t)` — длина одного окна на волне, её считает сервер (`scenario.clip_lengths`, поле `clips`).
- **Раунд «Три попытки»** (`round.kind = "three_tries"`, иначе `"regular"`; старый флаг `three_tries` переносит `normalize`): каждые три подряд идущих трека раунда — один исполнитель
  (`answer_groups`). Вопросы нумеруются «1.1, 1.2, 1.3, 2.1…» (`question_labels`), `{total}` — число исполнителей.
  Ответ — один слайд на исполнителя (`Renderer.answer_group_card`) сразу после его трёх вопросов, заставки «Ответы»
  в этом раунде нет. Сверху ответ/исполнитель первого трека, песни плавно проявляются по очереди (`group_frames`),
  каждая под свой отрывок. Видео на ответе в этом раунде не используется.
  У любого раунда может быть своя пауза перед вопросом `round.gap` (`gap_seconds()`, 0 допустим).
  У любого раунда может быть своё время ответа `answer_seconds` (`answer_seconds()`), в «Трёх попытках» — на каждую песню.
- **Озвучка заставок** (квиза и раундов): голос задаётся в `project.voice`, список — в `VOICES`.
  По умолчанию `ru-RU-DmitryNeural` из edge-tts: голос Microsoft, нужен интернет, пользователь выбрал его
  на слух, а голоса Piper ему не понравились. Голоса `ru_RU-…` — это Piper, запасной вариант без интернета;
  его модели скачиваются в `library/voices/`. Пусто — без озвучки. Готовая речь кэшируется в
  `library/voices/speech/` по хэшу голоса и текста. Сервис edge-tts отвечает нестабильно
  (`NoAudioReceived` на часть запросов), поэтому `speech` делает до 12 попыток с растущей паузой.
  Громкость речи выравнивается через `extract_fragment`, как у отрывков. Если диктор читает дольше
  `timing.intro`/`timing.round`, заставка удлиняется. Под озвучку можно подложить фоновую музыку:
  `project.intro_music` (заставка квиза), `project.outro_music` (финал), `round.music` (правила раунда
  и его «Ответы»). Значение — путь к файлу (`library/music/`) или ссылка (YouTube, скачивается в
  `library/youtube`, начало из `?t=`), см. `music_audio`. Громкость общая (`music_volume`). Каждый слайд
  запускает музыку с начала (`add_card` в `build`). Старое общее поле `music` при загрузке
  переносится в intro/outro (`normalize`).
  Текст для диктора отделён от текста слайда: `texts.intro_narration`, `round.narration`,
  `texts.answers_narration`, `texts.outro_narration` (с подстановками). На заставке квиза и раундов
  пустое поле означает, что читается текст слайда; на «Ответах» и финале — что озвучки нет.
- **Переносы строк:** текстовые поля трека в интерфейсе — `textarea.ml`, Enter переносит строку.
  `wrap_text` учитывает `\n` на слайдах, `track_label` для описания заменяет `\n` на «, ».
- **Вопрос:** круговой аудио-визуализатор по настоящему FFT отрывка (`spectrum_ring.py`), это
  отдельный модуль с настройками в `RingConfig`. Анимация такая: кольцо прорисовывается по часовой
  стрелке (`reveal_seconds`), потом убывает по часовой, как таймер. В центре цифры обратного отсчёта,
  на последних секундах всё краснеет. Синхронность картинки и звука проверена корреляцией:
  `lookahead_ms=40` компенсирует сглаживание.
- **Логотип на заставках:** полукруг-«солнце» из столбиков визуализатора (`SpectrumRing.draw_sun`,
  отдельный экземпляр `Renderer.sun` в масштабе 0.9, со всеми настройками и цветами визуализатора).
- **Шапка вопроса и ответа** (`Renderer._header`): слева `texts.round_label` («РАУНД {round_n}», шрифт
  заголовков) и название раунда (шрифт текста), справа плашка «Вопрос/Ответ X из X» (`round_side`).
- **Слайд ответа:** обложка альбома + название + исполнитель + альбом · год, фон — размытая обложка альбома.
  Видео на ответе: у трека поле `answer_video` (ссылка, начало из `?t=`). Тогда ответ идёт на фоне видео
  (`youtube.download_video` → `library/video/<id>.mp4`, до 1080p, кадры декодирует ffmpeg) с его звуком,
  поверх лежит `Renderer.answer_overlay` (затемнение снизу + шапка + тексты ответа слева внизу, без обложки альбома;
  раскладку как у ответа с обложкой альбома и без затемнения пробовали — пользователь вернул эту). Поле трека
  `video_source` (источник видео) — самая верхняя строка подписи. Шрифты подписи поверх видео
  уменьшены на `VIDEO_TEXT_SCALE` (0.75). В предпросмотре — стоп-кадр из начала видео (первый кадр `render_slide`).
  Звук на ответе по умолчанию `replay` (тот же отрывок), чтобы было понятно, к какому вопросу ответ.
- **Обложки альбомов** (`covers.py`): своя → вшитая (≥400 px) → кэш `library/covers/auto` → Deezer → iTunes →
  миниатюра YouTube (с обрезкой чёрных полей) → вшитая маленькая → нарисованная пластинка.
- **Скачивание** (`youtube.py`): yt-dlp вызывается как внешняя команда, `-f bestaudio/best`, кэш
  в `library/youtube/<id>.*` вместе с `.info.json` и миниатюрой. Метаданные берутся из полей
  `track/artists/album/release_year`, иначе разбирается заголовок. Начало отрывка берётся из `?t=`.
  Для YouTube yt-dlp нужен JS-движок. Зависимости ставятся через **uv** (так попросил пользователь):
  `pyproject.toml` + `uv.lock`, `package = false`, скрипты запускаются как `uv run make_quiz.py …`.
  yt-dlp[default] и deno (пакет из PyPI) ставятся в `.venv`. Проверено: под `uv run` yt-dlp
  находит deno (`JS runtimes: deno-…`). Из системы нужен только ffmpeg. yt-dlp обновляется
  командой `uv sync -P yt-dlp -P yt-dlp-ejs -P deno`.
- **Веб-конструктор** (`server.py` + `web/index.html`): только стандартная библиотека Python,
  без Flask и без сборки фронтенда. Слушает 127.0.0.1. Изменяющие запросы требуют заголовок
  `X-Quiz: 1`, Host проверяется (защита от чужих сайтов). Правки сохраняются по одному полю
  (PATCH), поэтому фоновые задачи не затирают ввод пользователя. Фоновые задачи: download,
  covers, preview (повторный запрос перерисовывает с новыми настройками), sheet, build.
- **Интерфейс:** палитра взята из ролика (сливовый #1A1230 + янтарный #FFC83D), шрифт Ubuntu Sans.
  У слайда ответа свои цвета текста (`style.answer_text`, `answer_muted`): его фон — размытая обложка альбома, а не общий фон.
  Главный элемент — волна трека с перетаскиваемым окном отрывка. Справа закреплён живой предпросмотр.
- **Данные:** `projects/<slug>/project.json` (пути относительно корня), общая `library/`.
  Оформление общее для всех квизов (так попросил пользователь): `library/theme.json` хранит
  `style`, `fonts`, `visualizer`, `timing` и подписи из `THEME_TEXTS`. `Workspace.load` накладывает
  оформление на квиз, `save` вырезает её из `project.json`, а `patch` отправляет такие пути в `patch_theme`.
  Поэтому правка цвета в любом квизе меняет все квизы. Название, приветствие, музыка, голос и раунды у каждого квиза свои.
  Шрифт задаётся как «путь#Начертание» (для вариативных шрифтов). В текстах есть подстановки
  `{n} {total} {songs} {seconds} {count}`. Пустой заголовок слайда убирает этот слайд из ролика.
- **Видео:** 30 fps, звук и картинка выровнены до сэмпла (1470 сэмплов на кадр), громкость −14 LUFS одним усилением без компрессии (тихое поднимается не больше чем на 6 дБ),
  кадры отдаются в ffmpeg через pipe, x264 veryfast crf 20, кольцо рисуется в `RENDER_THREADS` потоков. Дальше сборку ограничивает pipe и x264.

## Что проверить в первую очередь

1. `uv run make_quiz.py serve`, вставить 3–4 реальные ссылки (клип, трек YouTube Music, ссылку
   с `?t=`), убедиться, что они скачались и метаданные разобрались разумно.
2. Поиск обложек в Deezer/iTunes на реальных песнях, включая русскоязычные (страна iTunes задаётся
   в `covers.itunes_country`, по умолчанию `US`; для русских песен попробовать `RU`).
3. Миниатюры YouTube Music: проверить, что обрезка полей даёт квадратную обложку альбома.
4. Плеер в Firefox: перемотка (сервер отдаёт Range) и воспроизведение webm/opus.
5. Сборка полного ролика на 20–30 песен: время и итоговое видео.

## Команды

- **Все проверки: `mise run check`** — её же запускает pre-push и CI (`.github/workflows/check.yml`). Внутри:
  hk (ruff, ruff format, typos, Betterleaks, ast-grep, jactionlint), Betterleaks по всей истории, deptry,
  тесты правил ast-grep, pytest. `mise run fix` — безопасные автоисправления, `mise run vulns` — OSV-Scanner
  по `uv.lock` (нужна сеть). Версии инструментов — в `mise.toml`, Python-инструменты — в `uv.lock`.
  Хуки ставятся один раз: `mise exec -- hk install --mise`.
- Тесты: `uv run pytest -q` (`tests/`, нужен ffmpeg, около 35 с). pytest-xdist пробовали: медленнее, каждый тест сам грузит все ядра.
- Линтер: `uv run ruff check`, форматирование: `uv run ruff format` (строка до 120 символов).
- git есть (ветка `main`). Всё запускается через `uv run` (иначе не находятся yt-dlp и deno из `.venv`). Из системы нужен ffmpeg/ffprobe.

```bash
uv sync                                          # окружение
uv run make_quiz.py serve [--port 9000] [--no-browser]
uv run make_quiz.py new "Название" --links ссылки-пример.txt
uv run make_quiz.py add <slug> файл.txt
uv run make_quiz.py download|covers|preview <slug>
uv run make_quiz.py build <slug> [--limit 2] [--round "Раунд"] [--no-download]  # --limit: первые N из каждого раунда; --round: пробник раунда без общих заставок
uv run make_quiz.py --home <папка> …             # другой корень вместо папки со скриптами
uv run cover.py <slug> [--port 8790]             # отдельный конструктор обложки для соцсетей (cover.py + web/cover.html)
```

Связь с роликом — только через файлы. «Сохранить в квиз» пишет `projects/<slug>/cover.png`: если он есть, ролик
начинается с него вместо заставки квиза (`timing.cover` секунд или пока диктор читает приветствие
`intro_narration`, под `intro_music`), а значок YouTube делается из него.
«Сохранить логотип в оформление» пишет `library/logo.png` и `style.logo`: тогда заставки рисуют его вместо солнца
(`Renderer._logo`, в `LOGO_SCALE` раз выше солнца). Список раундов — два столбца без номеров, названия по центру
столбца (`Renderer.rounds_list`). Заставка раунда (`Renderer.round_card`): название, подзаголовок `round.subtitle` (до 3 строк)
(краткое описание), правила `round.rules` мелким шрифтом; весь блок поднят на `ROUND_LIFT` высоты кадра, логотип опущен к названию на `ROUND_LOGO_DROP`.

Сам `cover.py` в конструктор квизов не встроен: Python только раскладывает обложки альбомов квиза радугой
(`quiz_covers`, `grid_for`, `rainbow_layout`), а коллаж, засвет, логотип и тексты рисуются в браузере на canvas.
Настройки — `projects/<slug>/cover.json`, загруженные шрифты — `library/fonts/`.

## Архитектура

- `make_quiz.py` — argparse-оболочка. `server.py` — тонкий HTTP-слой над теми же функциями.
  `scenario.py` — сценарий ролика: чистая функция `build_scenario` возвращает список `Slide` (вид, кадры, подписи,
  треки, части звука `Clip`/`Silence`/`Narration`/`VideoClip`, фоновая музыка, глава) и правила раунда
  (`question_seconds`, `answer_groups`, `question_labels`…). Не читает файлы и не зовёт ffmpeg; длительность озвучки
  приходит функцией. `build` по сценарию нарезает звук, рисует слайды (`render_slide`) и считает главы (`chapters`).
  Предпросмотр берёт слайды из того же сценария (`preview_slides`): слайда, которого не будет в ролике, в нём нет.
  Побочные эффекты сборки собраны в `Media` (нарезка, диктор, музыка, видео ответа, кодировщик `FfmpegEncoder`):
  `build(..., media=...)`. Тесты подставляют `FakeMedia` из `tests/test_build_media.py` — звук слайдов и первый кадр
  проверяются без ffmpeg; через настоящий ffmpeg идёт один сквозной тест (`test_build_regular_round_answer_seconds`).
  Остальная логика лежит в `quiz_core.py`: `Workspace` (пути, блокировки проекта, чтение и запись
  `project.json`), `parse_track_list`, `Renderer` (слайды на Pillow), `preview`, `answers_sheet`,
  `download_tracks`, `find_covers`, `build` + `VideoWriter` (pipe в ffmpeg).
- Долгие функции ядра принимают `log`, `progress`, `cancel` (это `threading.Event`, при отмене
  выбрасывается `Cancelled`). В `server.py` `Jobs` запускает их в потоках, а `start_job`
  выбирает функцию по виду задачи.
- Схема проекта задаётся в `DEFAULT_PROJECT` / `DEFAULT_TRACK`. `normalize` подмешивает значения
  по умолчанию через `deep_merge`. Что можно менять через PATCH, решают белые списки `PATCHABLE`
  и `TRACK_EDITABLE`: новое поле, которое правится из интерфейса, нужно добавить и туда.
- `spectrum_ring.RingConfig` — единственный источник настроек визуализатора. `config_schema()`
  строит форму в интерфейсе, разбирая **исходник и комментарии** класса: строки-заголовки групп
  `# ── Заголовок. пояснение ──`, а у каждого поля комментарий-подсказка `name: type = value  # подсказка`.
  Если нарушить этот формат, параметр пропадёт из конструктора. В `project.json` в `visualizer`
  хранятся только изменённые параметры.
- `youtube.py` и `covers.py` от ядра не зависят: yt-dlp через subprocess, Deezer/iTunes через urllib.

## Правила кода

- **Изменение не готово, пока не проходит `mise run check`.**
- **Правила линтеров не отключаются, чтобы провести изменение.** Исключение — узкое (один путь или пакет и одно
  правило), с причиной рядом и только по решению человека. Где лежат: `pyproject.toml` (ruff, deptry),
  `_typos.toml`, `.betterleaks.toml`. Границы модулей из «Архитектуры» проверяют правила ast-grep в `rules/`.
- **Явные состояния вместо флагов.** Не `True/False` и не `has_x`/`is_x`, а значение с названием состояния:
  `"pending" | "done" | "failed"`, `"quiz_intro" | "social_cover"`. Новое состояние тогда добавляется без второго флага
  и без невозможных сочетаний. Старые флаги (`enabled`, `shuffle`, `cover_backdrop`…) переводятся, когда их трогают.
- **Длинные ясные имена лучше коротких.** `rounds_list`, `social_cover`, а не `rounds`, `cover`, если короткое
  можно спутать с другим понятием из `GLOSSARY.md`.

## Как проверять

- Быстро без браузера: `uv run make_quiz.py preview <квиз>` → кадры в `projects/<квиз>/output/preview/`.
- Сквозная проверка интерфейса удобна через Playwright (headless Chromium): добавить треки,
  перетащить окно на волне, загрузить шрифт и обложку альбома, собрать пробный ролик.

## Идеи, о которых говорили, но не сделали

- Форматы квиза без музыки (например, «угадай песню по эмодзи»), чтобы не упираться в Content ID.
- Возможно, пользователь захочет другую анимацию появления кольца: слово «погружаться» мы
  поняли как «прорисовываться по часовой».
